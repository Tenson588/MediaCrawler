# 版本说明：本地雪具情报报告工作台

发布日期：2026-10-20
适用分支：`main`

## 版本目标

本版本在 MediaCrawler 本地 API 上增加可视化监控报告工作台，将经销商和品牌数据分开管理，并提供可复查、可下载的 Markdown 与 PDF 报告。

## 主要变更

### 1. 本地报告工作台

- 新增 `/reports` 页面；前端未构建时，根路径也会进入该页面。
- 页面加载后自动检查 Python、核心依赖、采集程序、SQLite 数据目录和命令执行能力。
- 运行状态卡支持折叠；正常时使用绿色状态条，异常时自动展开并显示红色状态。
- 运行状态和数据版本时间集中显示在卡片左侧，服务操作按钮排列在右侧；历史报告使用图标删除按钮。
- 新增 `start_dashboard.py`，可一键启动服务并打开浏览器。
- 新增可双击的 `启动监控面板.command`，后台启动服务并清理由该启动器留下的无响应进程。
- 本地文件方式打开报告页时会连接 `127.0.0.1:8080` 并显示正确入口提示，避免请求被错误发送到 `file:///api`。
- 服务卡新增重启和关闭按钮；重启会先终止活动抓取任务，并在恢复后自动重新连接页面。
- 服务卡显示采集日志中的 401/403/429、验证码和 IP 限制信号，用于区分本地服务故障与平台访问限制。

### 2. 经销商与品牌独立工作区

- 页面分为“经销商”和“品牌”两个标签，分别展示统计、采集记录、报告设置和历史报告。
- 品牌记录根据专项关键词、品牌名称和已登记官方线索识别，经销商视图自动排除这些记录。
- 经销商报告保存在 `data/reports/`，品牌报告保存在 `data/reports/brand/`。
- 两类报告分别支持搜索、详情查看、Markdown 下载和 PDF 下载。

### 3. 主要品牌专项监控

- 可单独执行 Bogner、Atomic/Aomic、Salomon、HEAD、Burton、ThirtyTwo、卢西诺/Rossignol 的小红书监控。
- 任务会先补采已登记的 Burton 官方活动，再按品牌关键词搜索最新笔记。
- 采集过程复用当前 Python 解释器，并将结果写入本地 SQLite。

### 3.1 REV 头盔问题监控

- 新增独立“REV 头盔”工作区，专项采集负面评价、投诉、开裂破损、松动固定、撞击保护和佩戴视野问题。
- REV 记录从经销商和品牌数据中隔离，页面按型号、问题类型和关注等级展示。
- REV 风险报告单独保存，按高、中、一般关注排序并提供型号汇总；报告明确说明用户帖子属于待核实线索，不能直接作为安全隐患结论。

### 4. 报告内容与 PDF

- 报告开头显示促销候选线索总数，并为候选线索编号。
- 促销候选线索过滤明确属于非中国大陆的信息，并按冷山、傲天、黑桃/SPADERS、三夫/攀山鼠、其他的优先级排序；同级线索按发布时间倒序。
- 自动梳理折扣、价格、参加条件、排除款式、赠品、时间和渠道信息。
- 重点摘要优先展示最大优惠和最新动向，并突出价格、折扣信息。
- 生成参数和数据来源说明统一放在报告末尾的“备注”中。
- PDF 使用中文字体排版，保留正文层级、页码和可点击原文链接，同时打印完整 URL。
- PDF 在相邻促销候选线索之间绘制分割线，长报告中更容易辨认每条线索的边界。

## 数据与生成文件

以下本地内容不会提交到 Git：

- `database/*.db`：本地采集数据库。
- `data/`：本地 Markdown 报告。
- `output/`：界面截图和 PDF 预览。
- `browser_data/`：浏览器登录状态。
